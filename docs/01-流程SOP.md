# 五阶流程 SOP

流程是这套东西里唯一能复用的部分。模型换一代，流程可以不动。

## 0 · 问诊（先判断能不能做）

问清五件事，缺一件就先停：

1. **谁和谁**：双方是个人还是公司？对方主体信息有没有（名称、统一社会信用代码、住所地、法定代表人）
2. **什么事**：一句话说清争议事实，以及时间线
3. **手上有什么**：转账凭证、聊天记录、合同、发票、录音、照片
4. **要什么**：退款、还款、赔偿、解除合同、履行义务
5. **在哪**：合同履行地、被告住所地

判断：主体不明、事实说不清、证据缺口大、需要鉴定 → **不做**，直接说明原因。

## 1 · 归集（材料 → 一张表）

把当事人给的东西整理成三栏：**证据 / 时间线 / 诉求**。

- 证据：编号、名称、来源（微信/银行/平台/公示系统）、页数、证明目的
- 时间线：日期 + 发生了什么 + 对应证据编号
- 诉求：要什么 + 依据（合同条款 / 法条）

> 最容易跳过的一步。材料缺一项，后面全停。

## 2 · 检索（同类文书）

用案由 + 争议焦点做关键词，去找同类的公开文书，只挑能用来对照结构的几份。

**看什么**：诉讼请求怎么列、事实部分按什么顺序叙述、争议焦点怎么落到法条。
**不看什么**：别人的金额、别人的法院、别人的当事人信息。

## 3 · 起草（结构 + 要素）

按 `templates/_通用/` 的骨架写，把『1 · 归集』的要素填进结构。

顺序固定：当事人信息 → 诉讼请求 → 事实与理由（时间顺序）→ 法律依据 → 此致法院 → 签名日期。

写完自检：**每个数字都能指回证据编号**；指不回的删掉或补证据，不要留着。

## 4 · 校对（逐段，不跳）

逐段核三样：事实（和材料一致）、诉求（和事实匹配）、时间线（先后顺序正确）。

常见错：金额大写小写不一致、日期与证据对不上、被告主体名称与公示信息差一个字、管辖法院选错。

## 5 · 提交（当事人自己点）

- 给操作路径：注册 → 实名 → 选择法院 → 填写当事人信息 → 上传材料 → 提交
- 材料按「起诉状 → 证据清单 → 证据 1..n → 身份证明 → 送达地址确认书」顺序命名
- 提交后关注：受理通知、缴费通知、补正通知（补正有期限，别错过）

署名与提交都是当事人本人；这里只写操作指引。
