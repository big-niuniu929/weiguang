# 微光 · 民事文书模板库

> 把「不知道要准备什么材料、不知道文书怎么写」变成一条能照着走的流程。
>
> 这里放的是**结构，不是范文**：每一段写什么、写多长、按什么顺序，以及哪些空必须由当事人自己回答。
> 案例页：**https://big-niuNiu929.github.io/work/weiguang.html**

---

## 这是什么

2025 年 7 月起，我独立整理了 15 类常见民事纠纷的文书模板，并把「材料汇总 → 同类文书检索 → AI 初稿 → 人工逐段校对 → 提交指引」做成一条固定流程，累计协助 **89 人**完成在线提交、交付 **98 份**文书（口径见[页面](https://big-niuNiu929.github.io/work/weiguang.html)，咨询按人去重、文书按份计）。

这个仓库是那条流程里**可以公开的部分**：

| 目录 | 内容 |
|---|---|
| `templates/_通用/` | 4 类文书骨架：民事起诉状、证据清单、协助调查申请书、情况说明书 |
| `templates/<案由>/` | 15 类案由的要素表、必备证据、诉讼请求写法、常见抗辩、管辖提示 |
| `prompts/` | 五阶流程的分层提示词（问诊 → 归集 → 初稿 → 校对 → 提交指引） |
| `docs/` | 边界与免责、流程 SOP、脱敏规范、质量检查清单 |
| `examples/租房押金纠纷-虚构示例/` | 完全虚构的示例：一份填好的文书长什么样 |

## 边界（写在最前面）

- 不做任何专业身份的表述：不代理、不出庭、不签收法院文书、不承诺结果、不提供法律意见
- 文书以当事人本人名义提交，提交动作由当事人自己完成；这里只提供操作指引
- 公益性质，不设收费，不接受商业委托
- 模板不是范文。模板只回答「这一段写什么」；「这一段写什么**事实**」必须由当事人回答，答不上来就空着，不猜、不编

## 为什么模板要留空

小额纠纷看着简单，差异全在细节：有的卡在对方身份信息，有的卡在证据形式，有的卡在管辖。模板能覆盖结构，覆盖不了差异。所以差异被显式化——留空的地方必须由人来回答。

要素错一处，整份文书就失去意义，而当事人不会知道是哪里错的。这是这个仓库最重要的设计约束。

## 怎么用

1. 先在 `templates/` 里找到最接近的案由；对不上就用最接近的两类交叉看
2. 按该目录的「要素表」把事实填进 `要素清单.md`（答不上来的先空着）
3. 用 `templates/_通用/` 的骨架起草，`prompts/` 里的提示词只负责把要素填进结构
4. 逐段核对：每个数字、每个日期、每个当事人信息都能回到原始材料
5. 用 `docs/质量检查清单.md` 过一遍，再按 `docs/流程SOP.md` 最后一步操作

## 内容来源

结构来自实际交付过的文书（已全部脱敏），案由清单来自实际接待过的咨询。所有示例、占位符、虚构数据都不对应任何真实当事人、机构或案件。
